# 怎么拆（第 1 到 4 步）

什么时候读：做第 1 到 4 步之前。

`$S` 指本 Skill 所在的文件夹（`SKILL.md` 那一层），`$W` 指这次的工作文件夹。

## 第 1 步：全片过一遍

**建工作文件夹。** 用户说了放哪就放哪；没说就放在当前打开的文件夹下，起名 `<日期>_<账号名><内容类型>_剪辑拆解/`，名字里不要有空格。把每条片子复制进 `原片/`，改名成 `第一条.mp4`、`第二条.mp4`（最新的那条排第一）。原片原来放哪不动。原片要不要另外归档是用户自己的事，这里不替他做。

**先问一句或搜一下：这个账号以前拆过没有。** 以前拆过就把旧拆解找出来，第 4 步对着看时用（踩过的坑第 40 条）。

**每条片子跑一遍：**

```bash
zsh $S/scripts/pao.sh "$W" quanpian.py 原片/第一条.mp4 第一条
```

作者那台 Mac 上，两分多钟的片子跑不到半分钟。跑完读 `第一条/全片概况.txt`，三处必看：

1. **动作区间里超过 2 秒的有几段。** 动作区间占了全片大半（蓝球录屏风那条占 96%）时，动作条没用，改成看总览图自己挑帧段出画面条（踩过的坑第 32 条）。 多的话先看是不是画面角上一直有个真人小窗在动。是就加 `--bukan 左,上,右,下`（0 到 1 的比例）把那一块去掉重跑。红白大字风的小人在左下角，用的是 `--bukan 0,0.62,0.38,1`。
2. **换屏候选。** 它只抓得到整幅画面突然变的那种。2026-11-23 拿逐帧量过的答案核对：第一条 57 个换屏点对上 52 个，第二条 65 个对上 58 个；没对上的全是叠化、图挪着过去、先切黑再滑入这类不干脆的换屏，而且全部落在某个动作区间里。所以换屏点 = 换屏候选 + 看动作条补上的。候选里也有多出来的（闪白、甩动会连着出两三个），看图去掉。
3. **一直在轻微变的区间。** 真人画面、会动的视频片段、画面在慢慢推近或平移，都在这里面。逐段看（见第 2 步）。

**转口播文字。** 用手边能出时间戳的语音转文字工具转（Whisper、Qwen3-ASR 这类都行），带时间。识别错的词对着画面上的字幕改。没有逐句对着声音核的，在拆解文件里写明。

**屏数对不上、想再量一遍换屏时**，可以再找一个切镜头的工具切一遍当第二把尺子。作者用的是自己的一个还没公开的视频分析工具 rea-video：

```bash
zsh $S/scripts/pao.sh "$W" -- rea-video decompose --no-vlm --no-stems --no-asr -o 原始输出/rea_第一条 原片/第一条.mp4
```

不管用哪个工具，只取它量出来的切点和画面文字时间，它「判断」出来的东西不用（rea-video 就把真照片判成过 AI 生成，见踩过的坑第 15 条）。

## 第 2 步：一屏一屏拆

**总览图全部看完。** `第一条/总览/总览_NN.jpg` 每 0.2 秒一格，顶上有红条的格子是换屏候选。一张不落地看，边看边定屏：画面主体换了就算新的一屏；同一批图在屏内挪了位置、多出一张图，也算新的一屏（红白大字风第一条第 15 屏）。

**每屏填一行**，写进 `第N条_逐屏拆解.md` 的逐屏表：

| 列 | 写什么 |
| --- | --- |
| 屏号、起止帧、起止秒 | 帧号是原片的帧号，从 0 数 |
| 这句口播 | 这一屏时间里说的话 |
| 这句话在干什么 | 举例、对比、讲结构、给办法、过渡这类。这是你的判断，表头就写明 |
| 排法 | 用排法清单里的名字 |
| 画面里有什么 | 几张图、各是照片还是会动的片段还是真人、图上是谁（只写口播或画面文字点了名的） |
| 标注 | 种类（圆点、虚线、箭头、圈、量尺）、画在哪、先后顺序 |
| 大字 | 写什么、什么颜色、在哪 |

**看到这些信号要停下来多看几帧：**

- 一张「照片」的人在眨眼、有手入画：是视频片段，不是照片。
- 画面一帧一帧几乎不动，隔半秒看却大了一圈：在慢慢推近。`全片概况.txt` 里「一直在轻微变的区间」逐段用下面的命令隔 5 帧看一眼，分清是真人、片段还是推近：
  ```bash
  zsh $S/scripts/pao.sh --benji "$W" huamiantiao.py 原片/第一条.mp4 画面条/轻微变_1185.jpg 1185 12 5
  ```
- 字比图先出来；标注先悬在黑底上，图再滑到它底下。
- 换屏那一下不是切，是先切到纯色停几帧。

**归出两样东西：**

1. **排法清单。** 每种排法：长什么样、用了几屏、典型的一屏是哪屏。先数「一共有几种」。这类片子通常是十来种排法反复用（红白大字风两条一共 13 种，第一条里 4 种就占了 58 屏里的 34 屏）。表里可以用字母代号写得短，但清单里每个代号后面都要有全名，给用户看的话里不用代号。
2. **什么话配什么排法。** 按「这句话在干什么」分组，数每组各用了哪种排法几次。这是你归的，作者没说过，标「我的判断」。

**所有的数用脚本从表里数**，不手数。写一个十来行的小脚本读表格、按排法和「在干什么」计数，数出来的和你写的统计对不上就改文字。

**素材分几类也记下来**：照片、会动的片段、真人出镜、图表或解剖图、道具。各有多少张次（按摆放位置数；去重后的张数没数就写没数）。

## 第 3 步：一帧一帧量动效

**动作条全部看完。** `第一条/动作条/动作条_NN.jpg` 把每个动作区间逐帧排开，行首写着动作编号和帧段。没看的段落记下来，写进「没查」，不要按同类类推。

**每个动作记四件事：** 是什么东西在动（图、大字、标注、字幕、整幅画面）；怎么进来（滑、淡、弹、擦、逐字、直接出现）；从第几帧到第几帧；有没有退场动作（红白大字风几乎只有进场，没有退场，走的时候跟着换屏一起没）。

**先归类，再量。** 这是这一步最要紧的顺序：

1. 把所有动作按「看起来是同一种」分组。
2. 每组挑三处，量出每一帧的位置或透明度。位置用程序找亮像素的框，不靠眼估。量具可以从红白大字风那次的拿来改：`$S/examples/liangju/` 里的 `量图轨迹.py`、`量字和标注.py`、`量字幕.py`、`验证预设曲线.py`（是那一次用的原样，里面的文件名、坐标都是按那两条片子写的，要改了才能用）。
3. 三处对得上，这一组就是同一个预设，记成一条标准曲线，加上「每屏不同的只有：第几帧开始、走多远、用几帧」。
4. 对不上，再多量几处；确实每处都不一样的，记成「不是固定曲线」。

红白大字风量出来的，可以当对照：

- 图滑进来：13 到 15 帧，先快后慢。每帧走的距离按最快那一帧算是 0.98、1.00、0.99、0.97、0.92、0.85、0.75、0.64、0.52、0.40、0.29、0.19、0.11。横着滑和竖着滑是同一条。
- 叠化：直线。
- 大字淡入：约 13 帧（只在量得干净的 10 段上成立）。
- 大字一个字一个字从左边撑开：一个字的宽度每帧是满宽的 0.15、0.5、0.82、0.95、1。
- 标注沿线画出来：4 帧左右，每帧多画四分之一。
- 不是固定曲线的：闪白（三屏三个样）、放大糊进、翻开。

**看小东西时裁开放大看：**

```bash
zsh $S/scripts/pao.sh --benji "$W" huamiantiao.py 原片/第一条.mp4 画面条/屏12_左上的字.jpg 627 20 1 --kuang 0,0,0.6,0.3 --ge 320
```

**量不准的照实写「量不出」。** 白字压在白皮肤上、字底下的图也在动，按颜色分不出字从哪一帧开始亮（红白大字风第二条大字 138 处里有 24 处量不出）。不要编一个数。

**只出现一两次的特效，认出来、记下来、配一小段原片，不去量曲线。** 放射状拖影、带透视的翻页、光斑扫过、两张脸变形过渡这类，是剪映自带的特效。记：像剪映里的哪一类、在第几帧到第几帧、哪一屏。它们进「交给剪映」那一堆。

**字体。** 先在本机找最像的：剪映的字体缓存在 `~/Movies/JianyingPro/User Data/Cache/effect/`，系统字体也查。找到了写清是哪款、差在哪、要怎么压扁和倾斜。红白大字风的大字：最像的是思源宋体 Heavy，横向压到 76%、向右斜 10 度；原片的横画更细（约字高的 2.3%，这款约 3%），不是同一款，原片那款没认出来。

**声音。**

```bash
zsh $S/scripts/pao.sh "$W" -- rea-video decompose --no-vlm --no-asr --no-speakers -o 声音/rea_第一条 原片/第一条.mp4
zsh $S/scripts/pao.sh --benji "$W" shengyin.py 声音/rea_第一条/breakdown.json 第一条/全片概况.json 声音/第一条_声音对画面.md
```

`shengyin.py` 读的第一个文件是一份「音效时间表」，上面的命令是作者用 rea-video 出的。你手边没有这个工具时，换任何能找出音效起点的办法都行，整理成 `shengyin.py` 开头写的那种格式再喂给它；实在没有，就在说明包里照实写「声音没拆」。

出一张表：每个音效在第几帧、像什么声音、卡在换屏上还是卡在屏内某个动作开始上、差几帧；配乐从哪到哪。要回答的是：换屏配不配音效、哪类动作配音效、多久一个。这一步 2026-11-23 才第一次试，只在 30 秒的片子上跑过，音效找得全不全没有人听过。交付时照实写，并请用户或剪辑师听一遍。

## 第 4 步：几条对着看

逐项比，写成一张表：

| 比什么 | 第一条 | 第二条 | 结论 |
| --- | --- | --- | --- |
| 节奏（平均几秒一屏） | | | 固定 / 可选项 / 只这一条 |
| 排法（各用了几屏；有没有只在一条里出现的） | | | |
| 换屏的进法（各占几成） | | | |
| 每种动作的帧数和曲线 | | | |
| 大字的字体、颜色、出法 | | | |
| 标注的种类和画法 | | | |
| 真人出镜占全片几成 | | | |
| 角上小窗的样式 | | | |
| 声音（多久一个音效、卡在哪） | | | |

怎么下结论：

- 几条都一样：写成这种风格的规矩，标「固定」。
- 种类一样、比例不一样：写成可选项，不写死比例。红白大字风的换屏进法就是这样。
- 只在一条里出现：标「只这一条」，写明是哪条哪屏。
- 两条不一样、又必须定一个的（比如小窗样式）：以最新的那条为准。发布时间没查到就写没查到，不猜。
- 只有一条片子：全部标「只见于一条」。

这张表放进说明包。下结论用的每个数都要指得到逐屏表或动作清单里的出处。
