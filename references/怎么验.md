# 怎么验（第 5 步）

什么时候读：做第 5 步之前。

`$S` 指本 Skill 所在的文件夹（`SKILL.md` 那一层），`$W` 指这次的工作文件夹。验的产出都放 `$W/验/`。

验的目的是找出拆解里写错、漏写的地方，再改回拆解文件。目的不是把重做片做得和原片一样。三样都做，哪样没做在说明包里写「没验」。

## 验法一：留一条片子，只凭规矩猜它每屏怎么排

验的是「什么话配什么排法」这套规矩，换一条片子还成不成立。

1. 选一条当留出的片子。有两条就用其中一条归规矩、猜另一条；只有一条就用前一半归规矩、猜后一半，并在结果里写明这样做的短处。
2. 把留出那条每一屏的口播和起止秒数写成 `验/猜排法/题目.json`（屏、开始、结束、口播），真实排法另存 `验/猜排法/答案.json`。
3. 派一个没看过答案的 AI 来猜。任务说明照 [派给别的AI的话.md](派给别的AI的话.md) 第二份写。它只许读归规矩那条的拆解和题目，不许看视频、图片和留出那条的拆解。
4. 用脚本对答案，数三个数：
   - 完全猜中几屏。
   - 全猜「出现最多的那种排法」能中几屏。这是底线，猜中数要和它比才有意义。
   - 按「这句话在干什么」分组，各组猜中几屏。
5. 怎么读结果：
   - 猜中数比底线高不了多少：这套「什么话配什么画面」不能让 AI 自动套，「每屏用哪种排法」进「人来定」那一堆，AI 只能先配一版给人改。红白大字风就是这样：66 屏猜中 17 屏，底线 13 屏。
   - 某一组猜得准：这一组的规矩可以写成固定的。红白大字风里只有过渡的话准（6 屏中 5 屏，都是切回全屏真人）。
   - 留出那条用了规矩里没有的排法：记下是哪几屏，回去补排法清单。
6. 短处要写明：猜不中原片，不等于 AI 配的画面不能用。能不能用要用户或剪辑师看了才知道，这里验不了。

## 验法二：每种排法挑一屏，用程序重做，和原片逐帧比

验的是排法、位置、动作、帧数这些写得对不对。

**挑哪一屏。** 每种排法一屏，挑屏内动作最全的（有图进场、有标注、有大字）。只有一两次的剪映特效屏不挑，那些本来就不由程序做。排法超过十种时，先做用得最多的五六种，其余写「没验」。

**怎么做。**

1. **第一版只照拆解文件做，不看原片。** 这样才验得出拆解哪里没写清。先做后比。
2. 程序搭成「一屏一条数据」：排法、每张图的位置和进场、每个标注的坐标和出现帧、每段大字，都写在数据里，程序不为某一屏写死。
3. **素材只许三样：干净的静止照片、真人画面、声音。** 从原片截照片时，取标注和大字出现之前的那一帧；找不到干净的帧就抹掉字，并记下来。原片的过渡画面、标注、大字不许当素材。
4. 重做片按原片的宽高比和帧率出，放 `验/重做/屏NN/重做.mp4`，素材放 `验/重做/屏NN/素材/`。
5. 用什么程序做，看这种风格画面上主要是什么。照片加字加标注这一类，可以从红白大字风的渲染程序起：`$S/examples/liangju/` 里的 `复刻渲染.py`（那一次用的原样，要改了才能用）。网页界面动效一类，用你顺手的办法做（HTML 加截帧、Remotion 都行）。

**怎么比。**

```bash
# 这一屏在原片的第 627 到 681 帧
zsh $S/scripts/pao.sh "$W" yanshou.py 原片/第二条.mp4 验/重做/屏12/重做.mp4 验/重做/屏12/验收 --yuan-qi 627 --huanping 627
```

读 `验收结果.txt`。它量四个数：动法差（每个小块「这一帧比上一帧变了多少」，原片和重做相减，只看动得一不一样，超过 12 算没过）、整幅差（两边逐像素差的平均，超过 8 算没过）、清晰度（重做是原片的几成，低于 0.7 或高于 1.4 算没过）、小块差（只作参考）。主要看动法差。没过线的每一段都拼对照条看图：

```bash
zsh $S/scripts/pao.sh --benji "$W" duizhaotiao.py 原片/第二条.mp4 验/重做/屏12/重做.mp4 验/重做/屏12/对照_627.jpg 627 14 1 --yuan-qi 627
```

**过不过。** 一屏里动法差没过线的不超过 2 帧，算这一屏过了。红白大字风最后一版，第一条 58 屏里有 13 屏做到，第二条 66 屏里有 32 屏做到。

**没过怎么办。** 看图判断差在哪一类，对应着处理：

| 差在哪 | 怎么处理 |
| --- | --- |
| 拆解写错或漏写（帧数、位置、先后、漏了推近） | 改拆解文件，在说明包「被重做验出来的错」里记一笔，再改程序重做 |
| 字体不是同一款 | 不算拆解的错，记进字体一节 |
| 剪映自带的特效仿不出来 | 不仿，记进「交给剪映」那一堆 |
| 素材带着原片的字抹不干净 | 记进「没查」，有原始素材才能解决 |

对着原片最多改两轮。两轮还没过就收手，把还差在哪写下来。红白大字风的教训：往后越改越慢，第一条第二轮两个多小时只把对不上的帧降了 1.2 个百分点。

**每改一轮，和上一轮逐屏比。** 哪个数变差了当场退回。只看总数会漏掉改坏的屏。

## 验法三：把素材换成色块重跑

验的是重做片里的东西到底是程序画的，还是从原片贴上去的。

```bash
zsh $S/scripts/pao.sh "$W" sekuai.py 验/重做/屏12/素材 验/重做/屏12/素材_色块
# 重做程序不改，只把素材文件夹指到 素材_色块，原样再跑一遍，出 验/重做/屏12/证明.mp4
zsh $S/scripts/pao.sh "$W" sanlian.py 原片/第二条.mp4 验/重做/屏12/重做.mp4 验/重做/屏12/三联.mp4 --zheng 验/重做/屏12/证明.mp4 --yuan-qi 627
```

看证明片：灰格是照片，蓝格是视频。除了灰格和蓝格以外还在出现、还在动的东西，才是程序画的。原片里有、证明片里没了的东西（比如标注），就是跟着素材从原片来的，这一项不能算程序做到了。

如果重做程序是直接从原片里取素材的，就把原片本身换成色块：`sekuai.py 原片/第二条.mp4 验/原片色块`，再让程序读色块那条。

把「仍然来自原片的东西」列清楚写进说明包。红白大字风最后剩三样：一屏里的头骨图和黄色虚线弧、真人身上那圈白色虚线描边、真人画面里烧着的字幕。

## 尺子的规矩

- `yanshou.py` 归审的一方。做的一方不许改它，也不许换一把自己的尺子报数。
- 做的一方报的数，审的一方自己重量一遍再用。
- 只看数不够，每次都要看图。数骗过人的两次：每屏只比一帧，漏了过渡和先后；用糊的画面凑小了整幅差。
- 两台电脑上量出来要一样。`lib.py` 的读法已经保证了，另写读法前先看踩过的坑第 22 条。
- 没听声音、没核口型的，写「没查」。

## 给用户和剪辑师看
